# Todo API v1 实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development (recommended) or executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 用 Go 标准库实现内存版 Todo REST API（5 个端点 + 统一错误信封 + 分层测试），零第三方依赖，`go test ./...` 通过。

**Architecture:** `cmd/todo-api`（装配）→ `internal/httpapi`（HTTP 适配器）→ `internal/todo`（实体、校验、用例、`Store` 消费者接口）← `internal/store`（内存实现）。校验在业务层强制执行；`Store.Update` 用突变函数保证锁内原子读改写。

**Tech Stack:** Go 1.27（`http.ServeMux` 方法路由、`http.MaxBytesReader`、`log/slog`、`net/http/httptest`、`testing`），无第三方库。

**Spec:** `docs/superpowers/specs/2026-10-26-todo-api-design.md`

> **本计划的写法约定：** 按你的要求，本阶段不写产品代码。因此每个任务的测试用“用例表 + 断言要点”描述，
> 执行该任务时再用 TDD 落成实际 `_test.go`。签名（类型、函数、参数、返回值）是**确定的**，照抄即可。

## Global Constraints

- `go.mod` 不得出现任何 `require`；只允许标准库。
- 模块路径：`example.com/todo-api`（占位，将来可整体替换）。
- 所有导出标识符必须有 godoc 注释，句子以标识符名开头、句号结尾。
- 每个任务结束时 `go build ./...` 与 `go vet ./...` 必须通过；`gofmt -l .` 无输出。
- 错误通过 `error` 返回；除中间件的 `recover` 外不得用 `panic` 做流程控制。
- 长度按 **rune** 计：`utf8.RuneCountInString`。
- JSON 字段 camelCase；时间 RFC3339。
- 提交信息用 Conventional Commits：`feat(todo): ...`、`test(httpapi): ...`、`chore: ...`。
- 测试断言只用标准库（`t.Fatalf` / `reflect.DeepEqual` / `errors.As`），不引入 testify。
- 每完成一个任务，在回复里列出改动的文件（用户明确要求）。

## Review Focus

按“最可能咬到使用者”的顺序排列；每一条都在对应任务里有测试固定。

1. **并发写同一条待办**：两个 goroutine 同时 PATCH，不得丢更新、不得 panic，`go test -race` 必须干净 → 固定于 **Task 3**（并发测试）与 **Task 4**（突变函数原子性）。
2. **超大请求体**：>1 MiB 的 body 必须回 `413` 而不是把整包读进内存 → 固定于 **Task 5**（`decode_test.go`）。
3. **中文/emoji 标题**：200 个中文字必须通过、201 个必须 `400`；emoji 按 1 rune 计 → 固定于 **Task 2**（边界用例）。
4. **JSON 畸形输入**：`null`、`{}`、`[]`、`{"title":"x"}garbage`、未知字段、错误类型都必须是 `400` 且不 panic → 固定于 **Task 5** 与 **Task 6**。
5. **响应写入失败**（客户端断开）：`writeJSON` 编码/写入失败时只记日志、不得 panic 或二次写头 → 固定于 **Task 5**（`respond_test.go`）。

### Task 5: HTTP 编解码与错误响应

**Files:**
- Create: `internal/httpapi/respond.go`、`internal/httpapi/decode.go`、`internal/httpapi/respond_test.go`、`internal/httpapi/decode_test.go`

**Interfaces:**
- Consumes: `todo.ValidationError`、`todo.ErrNotFound`。
- Produces:
  - `const maxBodyBytes = 1 << 20`
  - `func writeJSON(w http.ResponseWriter, status int, v any)` — 设 `Content-Type: application/json; charset=utf-8`，只写一次状态码，编码失败只记日志不 panic
  - `type apiError struct { Status int; Code string; Message string; Details []fieldDetail }`，`func (e *apiError) Error() string`
  - `type fieldDetail struct { Field string `json:"field"`; Message string `json:"message"` }`
  - `func (e *apiError) write(w http.ResponseWriter)`
  - `func mapError(err error) *apiError` — `ErrNotFound` → 404 `NOT_FOUND`；`*todo.ValidationError` → 400 `VALIDATION_ERROR` + details；其他 → 500 `INTERNAL`（固定文案 `internal server error`）
  - `func decodeJSON[T any](w http.ResponseWriter, r *http.Request) (T, *apiError)` — 校验 `Content-Type`、套 `http.MaxBytesReader`、`DisallowUnknownFields`、拒绝尾随 token
  - `func parseID(r *http.Request) (int64, *apiError)` — `r.PathValue("id")` 必须是纯十进制且 `> 0` 且能放进 int64

- [ ] **Step 1: 写 `decode_test.go`**

| 用例 | 输入 | 期望 |
|---|---|---|
| 正常 | `Content-Type: application/json`，体 `{"title":"x"}` | 解码成功 |
| 带 charset | `application/json; charset=utf-8` | 成功 |
| 无 Content-Type | 体合法 | 415 `UNSUPPORTED_MEDIA_TYPE` |
| 错误类型 | `text/plain` | 415 |
| 语法错误 | `{"title":` | 400 |

| `null` 体 | `null` | 400 |
